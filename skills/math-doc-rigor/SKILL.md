# 数学文档严谨化工作流

把一条数学主张，从"想法"推进到"可归档的严谨文档"。核心是**先算后说**与**如实分层**——
这两点决定了这类文档可信不可信。

## 这个技能解决什么

数学与理论物理文档最容易出的两类问题：

1. **说了但没算**：断言看起来合理，但没有数值或显式推导支撑（如"相变处 γ 跳变"实为粗扫伪影）。
2. **把结构性说成等价**：主题上的呼应被写成严格的等价（如"γ_ren = c·η(0)"其实不成立）。

本技能用一条固定流水线来防这两类问题：**写 → 算 → 分层 → 体检 → 导出 → 归档**。

## 何时使用 / 不使用

- **用**：单篇数学/理论文档的撰写与修订、结论严格度标注、LaTeX 渲染安全体检、公式保真导出 PDF、
  仓库归档规范。
- **不用**：纯翻译、纯摘要、非数学的通用写作、与文档无关的数据处理。

## 六步工作流

流程是顺序的，但允许回退——第 2 步算出反例时，回到第 1 步改写。

### 第 0 步：环境准备

依赖：`markdown2`、`weasyprint`、`fonttools`（Python）+ `mathjax-full`（Node）。

- **Linux / macOS**：`bash scripts/setup.sh`
- **Windows**：`powershell -ExecutionPolicy Bypass -File scripts/setup.ps1`

> ⚠️ **沙箱/容器环境每次会话都会重置 pip 依赖。** 若 `md2pdf.py` 报
> `No module named 'markdown2'`（或静默回退、报"成功 0 失败 1"），先重装：
> `python3 -m pip install -q markdown2 weasyprint fonttools`

MathJax 装在**技能目录之外**（技能目录内不能有 `node_modules`：体积大、文件数多会导致注册失败），
用 `MATHJAX_NODE_PATH` 指定路径；不设时默认在脚本同级的 `node_modules` 找。

> **Windows 提示**：`weasyprint` 在 Windows 上还需 GTK3 运行库，否则报 `libgobject-2.0-0.dll` 找不到。
> **不必强行装 GTK**——`md2pdf.py` 在 weasyprint 不可用时会**自动回退到 headless Edge/Chrome**（`--print-to-pdf`），
> 同样能出公式保真的 PDF（打印时会在文件名后括注实际引擎）。装 GTK3 只是让 weasyprint 这条路径也可用。

### 第 1 步：草拟或读解

- **从零写**：先明确"这篇要主张什么"，用一句话写出来（主张句），再展开。
- **读解他人文档**：区分三类内容——**原文主张**、**你的补强**、**你的订正**，三者要标清楚，不要混为一谈。
- 立刻给文档一个"定位"（草稿 / 笔记 / 综述 / 正稿），归档方式取决于它。

### 第 2 步：验证（先算后说）

**这是本技能的核心要求**：每条非平凡断言，在写下它之前先拿到证据。

- **数值验证**：写脚本算出来（如相变的临界点、γ 的数值、收敛行为）。数值要**细扫**——
  步长过粗会造出假象（假跳变、假平台）。
- **显式推导**：把关键式子推一遍，检查系数（单模凝聚幅度是 `v² = −2ε_k/u`，不是 `−ε_k/u`）。
- **代数/群论断言**：逐元素验算，不靠直觉命名子群或商群（"阴阳 = g⁵"就是跳过了验算）。
- 把数值证据（脚本 + 结果）留在工作区，作为文档的支撑材料。

### 第 3 步：三层标注

对文档里每个结论，标注其严格程度（定义见 `references/rigor-levels.md`）：

- **严格**：有完整推导或已证定理支撑；
- **半严格**：有数值/启发式支撑，但缺严格证明；
- **结构性**：是框架内的结构性观察，不是可证的等价。

> 标注不是自谦，而是**信息**。三层混在一起，读者无法判断哪条能引用。
> 尤其禁止把"结构性"写成"严格等价"。

### 第 4 步：渲染安全体检

在导出前跑：

```bash
python3 scripts/check_md.py 文档.md
```

检查项见 `references/render-rules.md`。重点：**数学环境零中文**、**每行至多 1 个行内公式**、
**无风险宏**（tag / boxed / overset / xrightarrow 等）、行内公式用反引号写法、
**无缺字形字符**（emoji 在 PDF 字体栈里没有字形，见规则 10）、
**粗体 `**` 无 flanking 断裂**（见规则 11）。
有问题就修，直到"合计隐患: 0"。

> 脚本自带回归夹具 `scripts/tests/regression_fixture.md`：应当报出 **2 类隐患**
> （缺字形 2 种 + 粗体断裂 1 处），且对 `2 ** 3`、代码块、`中文**粗体**中文` 零误报。
> 改动 `check_md.py` 后跑一遍，即可确认没改坏。

### 第 5 步：导出与打包

```bash
MATHJAX_NODE_PATH=<setup 回报的路径> python3 scripts/md2pdf.py --outdir pdf 文档1.md 文档2.md ...
```

- 公式用 **MathJax 渲染成内嵌 SVG**（保真，不靠文本替换），再由 weasyprint 出 PDF。
- 文档里的相对图片路径（如 `figures/x.png`）靠 `base_url` 解析，**确保图片在文档同目录的相对路径下存在**。
- 多份文件一次传入即可批量；脚本会逐份汇报"公式 n/n"，失败的不会中断整批。

### 第 6 步：归档

按 `references/archive-conventions.md`：

- **公理本体 / 正稿** → 归 `axioms/`；
- **衍生材料**（补注、读解、形式化、综述、实例库）→ 归 `notes/`；
- 图片 → 与文档同一 `figures/` 目录，文档内引用用**相对路径**；
- 提交前**给用户看文件清单与 commit message 草案，确认后再提交**。

## 确认门（重要）

以下节点**停下来等用户确认**，不要自作主张：

1. 订正他人文档中的断言（改动别人的结论前先报告）；
2. 归档位置（axioms/ 还是 notes/）；
3. 提交前的文件清单与 commit message。

## 两个示例

**示例一：修订一篇他人文档**
用户给来一份"结构化分析"，其中一条断言的系数不对。
→ 第 2 步先算，发现系数差一个因子；第 1 步订正并**明确标注这是"订正"**；
→ 第 3 步给新结论标"半严格（数值）"；第 4/5 步体检并出 PDF；第 6 步给出 commit 草案待确认。

**示例二：从零写一份综述**
用户要求把三个不同领域的模型并置比较。
→ 第 1 步先写主张句（"三者同宗于同一套公理"）；第 2 步核对每条的出处；
→ 第 3 步逐条标注严格度（**不许把三者的共性说成"同一个"**）；第 5 步出 PDF；第 6 步归 `notes/`。
