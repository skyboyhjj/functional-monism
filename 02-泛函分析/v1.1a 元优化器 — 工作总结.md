
## v1.1a 元优化器 — 工作总结

### 问题背景

v1.1 的网格搜索发现粗搜（θ=0.02, σ=0.3056, MW=54.8%）与细化（θ=0.02, σ=0.2589, MW=45.3%）结果不一致。分析表明根因有三：

1. **粗搜统计噪声**：5 runs × 500 steps 的标准误差 ±3.4%，54.8% 可能是 +2σ 涨落
2. **步数效应**：500 步中扰动占 16%（vs 2000 步的 4%），瞬态放大了 MW 占比
3. **θ 卡在边界**：θ=0.02 是搜索范围下界，真实最优可能在范围之外

### 两项改进

#### 一、共同随机数（CRN）

**问题**：不同参数组合使用不同随机种子（`seed + i * 137`），导致参数间的比较不公平——一组参数可能恰好抽到"幸运"的随机序列。

**根因修复**：发现 `OUNoise.step()` 使用 `np.random.randn()`（全局随机状态），而非 `rng = np.random.RandomState(seed)`。即使传入了 seed，全局状态也不受控。

```python
# 修复前：OUNoise.step() 使用 np.random.randn()，不受 seed 控制
dW = np.random.randn(self.dim) * np.sqrt(self.dt)

# 修复后：在 run_single_simulation 中设置全局种子
np.random.seed(seed)  # 确保 OUNoise 中的全局随机可复现
```

**CRN 机制**：生成一组固定种子序列，所有参数组合共用：

```python
rng = np.random.RandomState(2026)
fixed_seeds = [int(s) for s in rng.randint(0, 2**31, size=n_runs)]

# 参数 A 和参数 B 使用相同的种子序列
simulate_with_params(theta=0.02, sigma=0.30, fixed_seeds=fixed_seeds)
simulate_with_params(theta=0.05, sigma=0.28, fixed_seeds=fixed_seeds)
```

**验证**：

```
相同参数 + 相同种子 → 完全相同结果 ✅
  第一次: {'mw_ratio': 0.5633, 'mw_dwell': 56.33}
  第二次: {'mw_ratio': 0.5633, 'mw_dwell': 56.33}
```

**CRN 的核心价值**：方差缩减。不同参数组合面对相同的"随机世界"，差异仅来自参数本身，而非运气。

| 对比 | 无 CRN (v1.1) | 有 CRN (v1.1a) |
|:---|:---|:---|
| 粗搜 θ | 0.02 | 0.021 |
| 细化 θ | 0.02 | **0.014** |
| 粗搜 vs 细化一致性 | ❌ 方向偏移 | ✅ 方向一致 |
| 粗搜 σ | 0.306 | 0.267 |
| 细化 σ | 0.259 | **0.290** |
| 结果可靠性 | 粗搜假阳性 | 粗搜与细化方向一致 |

#### 二、扩展 θ 搜索范围

**问题**：v1.1 的 θ 搜索范围是 [0.02, 0.15]，粗搜和细化都将 θ 推到下界 0.02，说明真实最优可能在范围之外。

**调整**：将 θ 下界从 0.02 扩展至 **0.005**，搜索范围变为 [0.005, 0.15]。

```
v1.1:  θ ∈ [0.02, 0.15]  → θ 收敛到 0.02（边界）
v1.1a: θ ∈ [0.005, 0.15] → θ 收敛到 0.014（内部）
```

**发现**：扩展后 θ 不再卡在边界，而是收敛到 0.014 附近，说明真实最优在 0.005-0.02 之间——之前被搜索范围遗漏了。

### 经验教训

1. **全局随机状态是隐患**：`np.random.randn()` 不受 `RandomState(seed)` 控制，必须在调用前设置 `np.random.seed()`。这类问题在随机模拟中隐蔽且致命。

2. **CRN 是方差缩减的一阶手段**：在比较不同参数的随机模拟时，CRN 应作为默认配置，而非可选优化。

3. **边界效应是搜索范围的信号**：如果优化器持续将参数推到边界，说明搜索范围需要扩展——这比盲目调整参数更重要。

4. **粗搜精度不是越高越好**：快速粗搜的目的是定位候选区域，而非精确评估。CRN 让粗搜更可靠，但不改变其"定位工具"的本质。
